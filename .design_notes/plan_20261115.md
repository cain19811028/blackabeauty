## 一、背景

你希望用 three.js 把整個網站的版面、圖片和美學升級，看起來像專業設計團隊重新設計過，主題仍然是賣碩博士服。

現在的木棉草地版其實已經是 2.5D：圖層分開、依深度做視差，用的是 CSS。要有明顯的升級，得靠 three.js 做三件現在做不到的事：

1. **手繪會動起來**：布料擺動、上萬根草隨風起伏。
2. **真正的鏡頭**：有正確的透視和景深。
3. **有遠近的大量花瓣。**

---

## 二、方向評估：全 3D 和 2.5D 手繪

| | 全 3D | 2.5D 手繪 |
| :--- | :--- | :--- |
| 袍服的樣子 | 重新用程式建模，可能不如手繪 | 就是現在的插畫 |
| 360° 旋轉、看披肩背面 | 可以 | 不行；鏡頭只能小幅擺動。背面可以另外畫一張，做成「正面／背面」切換 |
| 換色 | 可以 | 可以 |
| 和其他段落的插畫風格 | 會有落差 | 一致 |
| 手機負擔 | 較重 | 輕很多 |
| 最大的風險 | 袍服建模的品質。沒有 3D 美術做的模型，只能靠程式產生 | 貼圖銳利度（原型已驗證）、場景插畫的精緻度 |

**結論**：採 2.5D 手繪。全 3D 最大的不確定是袍服可能不如手繪好看。上次重畫「關於我們」的人物沒有通過，這類風險不該再冒。2.5D 用的就是已經認可的插畫。

## 三、原型（已完成）

**怎麼開**：雙擊 `proto/index.html`。它是獨立的一頁，不動主站。合併後也可以用 GitHub Pages 的 `/proto/` 開。

### 3.1 原型裡有什麼

| 項目 | 內容 |
| :--- | :--- |
| 袍服 | 同一套手繪插畫，在執行時轉成貼圖，貼在可變形的網格上，下擺會隨風擺動。人台和支架是另一層，固定不動 |
| 草坪 | 桌機 9 萬根草葉、手機 2.2 萬根。隨微風起伏，陣風由左往右掃過，滑鼠滑過會把草撥開。袍服在草地上有影子 |
| 方帽 | 真 3D，用三階色調的卡通渲染。開場時翻轉拋起、落在人台上，帽穗用彈簧物理擺動 |
| 鏡頭 | 真實的透視鏡頭。滑鼠讓鏡頭橫移，往下捲時鏡頭往前推 |
| 景深 | 前景木棉枝和遠景校舍以模糊貼圖呈現 |
| 花瓣 | 木棉花瓣和整朵花分成前後兩個深度帶，會從袍服的前面和後面經過 |
| 控制面板 | 四個效果的開關、「起風」、「再拋一次方帽」、「銳利度比對」 |

### 3.2 檔案

| 檔案 | 用途 |
| :--- | :--- |
| `proto/index.html`、`proto/proto.js` | 原型本體 |
| `proto/build-art.mjs` | 從 `index.html` 和 `css/tokens.css` 取出現有插畫，產生 `proto/art.js`。插畫更新後要重跑：`node proto/build-art.mjs` |
| `proto/art.js` | 產生出來的插畫資料，不要手改 |
| `proto/vendor/three.min.js` | three.js r187（MIT），打包成單一檔案 |

### 3.3 驗證

- **可以雙擊開啟**：主控台沒有錯誤。
- **銳利度**（原本最擔心的風險）：
  - 條件：GPU 點陣化加 1.25 縮放（你的環境）。
  - 方法：向量原圖和 three.js 貼圖並排，放大 4 倍比對。
  - 結果：邊緣平滑、沒有鋸齒，貼圖只略軟一點。
- **流暢度**：無頭 Chrome（RTX 4060 Ti）桌機 60fps；模擬手機尺寸 52～60fps。**還沒在真實手機上測過。**

### 3.4 原型的限制

- 場景插畫還是簡單版，校舍和丘陵沒有畫細。
- 只有 Hero 這一幕，沒有主站的其他段落。
- three.js 是整包 732KB。正式版只會打包用到的部分，約 150KB（gzip）。
- 「減少動態」開啟時，只顯示靜止畫面。

## 四、若採用 2.5D：要做什麼

### 4.1 Hero 場景

- 把原型併入主站，取代現在的 CSS 分層 Hero。
- **把場景畫細**：校舍的細節和明暗、有體積感的木棉樹、草坪上的層次和落花。這一步決定看起來像不像專業團隊做的。
- 現在的木棉草地版插畫留下來，當作載入前的畫面，也當作不支援時的備援。
- 捲動時鏡頭往前推過草坪，最後接到撕紙邊，和下一段銜接。

### 4.2 學位服展廳

- 鏡頭依序滑到學士、碩士、博士袍，每件都穿在人台上。
- 換色：只列原照片裡實際有的顏色。
- 不能 360° 旋轉。如果背面的披肩很重要，另外畫一張背面插畫，做成「正面／背面」切換。

### 4.3 全站版面升級

3D 只放在 Hero 和展廳。其餘段落做一輪編輯式的重新排版：

- 標題更大、更有層次，段落加上編號和直書點綴。
- 改用不對稱的版面，消掉大片空白。
- 卡片、表格、院校牆、頁尾重新設計。
- 桌機加上慣性平滑捲動。

### 4.4 全站花瓣

木棉花瓣改成有遠近的版本，貫穿整頁。

## 五、技術做法

| 項目 | 做法 | 理由 |
| :--- | :--- | :--- |
| three.js 的載入 | 用 esbuild 打包成單一的一般 script，放在 `vendor/` | three.js r187 只提供 ES module，而 `file://` 不能載入 module。這樣才能維持「雙擊就能開」 |
| 插畫變貼圖 | 執行時把 SVG 字串轉成 data URL，畫到 canvas 再當貼圖 | `file://` 下 WebGL 不能從磁碟讀圖檔；這樣也不必另外輸出圖片 |
| 顏色 | 關掉 three.js 的色彩管理，顏色原樣通過 | 貼圖顏色要和頁面上的 SVG 完全一致 |
| 貼圖銳利度 | ① 依螢幕上的實際大小繪製。② 鏡頭停下 0.35 秒後，依新的距離重畫。③ 取樣帶 -0.45 的 LOD 偏移 | 貼圖比螢幕大太多時，會被 mipmap 弄軟 |
| 貼圖邊緣 | 預乘透明度加 mipmap | 縮小時邊緣不會出現暗邊或白邊 |
| 布料擺動 | 袍服是 20×36 格的網格，在頂點著色器裡位移；位移量往下擺遞增，肩膀釘住不動 | 布料會動，插畫本身不變形 |
| 草坪 | 每根草是一個三角形，用 instancing 一次畫完；風、陣風、滑鼠都在著色器裡算 | 9 萬根草只要一次繪製呼叫 |
| 繪製順序 | 花瓣分成前後兩個深度帶，用 `renderOrder` 固定順序 | 袍服邊緣要保持平滑的半透明，所以不寫入深度 |
| 分級與備援 | 桌機完整版；手機減量版（草和花瓣減量、像素比上限 1.5）；不支援 WebGL、太舊的裝置或「減少動態」時，退回插畫版 | 多數客人用手機看 |
| 載入 | 文字和撥號按鈕第一時間出現；three.js 在背景載入，場景好了再淡入 | 首屏不能變慢 |

**效能預算的調整**：`plan_20261003.md` §8.3 的「JS 合計小於 40KB（gzip）」會超過，three.js 約 150KB。這是刻意的取捨，條件是 three.js 延後載入、不擋首屏。

## 六、風險與對策

| 風險 | 現況 | 對策 |
| :--- | :--- | :--- |
| 貼圖不夠銳利或有鋸齒 | 原型在 GPU 加 1.25 縮放下驗證過，靜止時和向量圖幾乎相同 | 每個里程碑都重跑同樣的比對 |
| 場景插畫不夠精緻 | 還沒做；原型用的是簡單版 | 先只畫細一個元素（例如校舍）給你看，通過再畫其他的。**不畫任何人物** |
| 3D 方帽和手繪袍服不搭 | 原型裡可以直接看 | 不搭的話，方帽改回手繪，拋帽維持現在的 2D 做法 |
| 真實手機的流暢度和耗電 | **還沒測** | 併入主站前，先用實機測原型；不夠順就讓手機直接用插畫版 |
| 載入變慢 | 還沒量 | three.js 延後載入，只打包用到的部分 |

## 七、不會變的事

- **客戶的決定**：木棉花、草地、人台落地、雲少、「聯絡我們」簡化版、「關於我們」用原版紅袍圖。
- **文案**：原文和店家資訊逐字保留；文字仍然是一般的 HTML，搜尋引擎讀得到。`check-content` 維持 100/100。
- **雙擊 `index.html` 能開。**
- **驗收方式**：GPU 點陣化加 1.25 縮放放大檢查邊緣、量測捲動流暢度、用比對頁對照前後版本。
